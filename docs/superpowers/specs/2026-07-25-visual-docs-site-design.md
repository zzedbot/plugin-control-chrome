# 通用 Chrome Agent 桥接器可视化文档站设计

日期：2026-07-25

## 1. 目标

将项目现有 README、架构、API、安全和 Codex 差异文档转换为可在本机浏览器运行的多页面可视化技术文档站。网站面向开发者，帮助读者从整体结构进入具体协议、接口和安全边界，而不是把 Markdown 原文简单搬到网页上。

除 MCP、JSON-RPC、Native Messaging、CDP、Manifest V3、API 等无法准确替代或需要与代码保持一致的名词外，页面文案以中文为主。所有技术结论必须可追溯到现有项目文档和实现，不新增未经验证的能力声明。

## 2. 交付边界

### 包含

- 本机运行的多路由文档站
- 中文化、结构化的全部现有文档内容
- 架构关系图、请求流演示、能力矩阵、API 浏览器、安全模型和 Codex 差异矩阵
- 本机安装与验证向导
- 全局搜索、键盘导航、响应式布局和少量本机偏好保存
- 内容完整性与工程构建验证

### 不包含

- 公网部署
- 用户账号、服务端数据库或云端同步
- 从文档站直接调用真实 Chrome
- OpenAI 私有代码、协议、品牌或扩展身份
- 在文档站中收集浏览器历史、Cookie、密码或其他敏感数据

## 3. 信息架构

网站采用固定侧栏和多页面路由：

| 页面 | 路由 | 核心目的 |
|---|---|---|
| 首页 | `/` | 回答项目是什么、解决什么问题、如何阅读 |
| 架构总览 | `/architecture` | 展示六层系统、组件职责、控制面和信任边界 |
| 请求全过程 | `/request-flow` | 演示一次浏览器操作在各层之间的往返过程 |
| 能力地图 | `/capabilities` | 按类别和完成状态浏览全部能力 |
| API 浏览器 | `/api` | 搜索、筛选和查看方法、参数、结果、错误及示例 |
| 安全模型 | `/security` | 展示威胁、默认保护、授权路径和生产加固项 |
| Codex 差异 | `/codex-differences` | 对比架构、能力、复用边界和兼容性 |
| 安装与验证 | `/setup` | 以步骤向导完成本机构建、安装和连接验证 |

全站提供：

- 固定侧栏导航
- 面包屑
- 上一页和下一页
- `Ctrl/⌘ + K` 全局搜索
- 当前页面目录
- 移动端抽屉导航

## 4. 视觉语言

采用用户确认的 A 方案“技术书刊”。

### 视觉特征

- 暖白纸张背景，而不是仪表盘式深色背景
- 编辑式排版，标题具有技术书刊气质
- 正文使用清晰的中文无衬线字体，长文阅读优先
- 大标题可使用克制的中文衬线字体形成章节感
- 朱红色只用于当前导航、关键流向和警示重点
- 深墨色用于正文和代码，不使用霓虹发光或大面积渐变
- 卡片和边框尽量少，仅在需要表达分组、状态或交互时出现
- 图形使用 CSS、HTML 和现有图标组件，不制作无必要的装饰插图

### 建议颜色

| 用途 | 色值方向 |
|---|---|
| 页面底色 | 暖白 `#F7F3EA` 附近 |
| 次级底色 | 纸灰 `#EEE8DC` 附近 |
| 正文 | 墨黑 `#28231D` 附近 |
| 次级文字 | 暖灰 `#746D62` 附近 |
| 主强调 | 朱红 `#C94A32` 附近 |
| 安全通过 | 深绿，避免荧光 |
| 差异与限制 | 琥珀色 |
| 未覆盖或高风险 | 暗红色 |

颜色必须满足正文和交互控件的可访问性对比度要求。

## 5. 页面设计

### 5.1 首页

首屏使用一句明确结论介绍项目，并展示从 Agent 到网页的六层简化链路。链路下方提供三个阅读入口：理解系统、接入开发、评估安全。

首页不使用无实际依据的百分比或营销指标。可展示可验证数量，如 API 方法数量、文档主题数量和系统层级数量。

### 5.2 架构总览

中心图展示：

```text
第三方 Agent → MCP/JSON-RPC → 本机宿主 → Native Messaging → Chrome 扩展 → CDP/Chrome API → 网页
```

点击组件后显示：

- 主要职责
- 输入和输出
- 依赖对象
- 使用协议
- 安全边界
- 失败后影响
- 对应代码文件

页面提供“数据流、权限边界、故障路径”三个视图，不在同一画面堆叠所有信息。

### 5.3 请求全过程

使用步骤播放器演示 `browser.click`：

1. Agent 调用 MCP 工具
2. MCP 将调用映射为 JSON-RPC
3. 本机宿主读取运行实例并验证随机令牌
4. 本机宿主检查站点策略
5. Native Messaging 把命令交给扩展
6. 扩展通过定位器寻找唯一元素
7. CDP Input 发送鼠标事件
8. 结果和事件沿原路径返回

每一步可展开查看示例数据，但敏感令牌使用掩码表示。播放器支持前进、后退、暂停、重新开始和键盘控制，并遵循“减少动态效果”设置。

### 5.4 能力地图

按以下类别展示：

- 浏览器与标签页
- 页面观察
- 页面交互
- 坐标与视觉执行
- 文件、下载和对话框
- CDP 与事件
- 历史、书签和敏感元数据
- 权限与安全策略

状态采用：已实现、功能等价、存在差异、未覆盖、不可复用。筛选结果支持链接到相关 API 和 Codex 差异说明。

### 5.5 API 浏览器

API 数据以结构化对象维护，页面由数据生成，不手工复制多个版本。

详情包含：

- 方法名
- 中文用途
- 所属类别
- 风险级别
- 必填和可选参数
- 参数类型及限制
- 返回结果示例
- 常见错误
- JSON-RPC、MCP 或 JavaScript 调用示例
- 相关能力和安全策略

列表支持中文、英文方法名和错误码搜索。代码块提供复制按钮和明确的成功或失败反馈。

### 5.6 安全模型

安全页采用信任边界图，而不是纯文字风险清单。图中区分：

- 第三方调用者
- 本机 IPC
- Native Messaging
- Chrome 扩展权限
- 网页和页面内容
- 用户数据和敏感元数据

点击风险节点后展示威胁、现有保护、残余风险和生产加固建议。默认拒绝、站点允许列表、阻止列表优先、CDP 白名单、敏感元数据开关和扩展本地停用开关必须清楚呈现。

### 5.7 Codex 差异

差异页包含架构比较和能力比较两部分。每项使用统一状态定义：

- 等价：用户可观察功能和架构角色相同
- 同类实现：使用相同公共原语，但代码和协议不同
- 存在差异：主要用途相同，细节或覆盖范围不同
- 未覆盖：当前项目没有提供
- 不可复用：涉及私有代码、身份、协议或产品服务

页面必须明确说明本项目不与 OpenAI 扩展或 Native Host 线协议兼容。

### 5.8 安装与验证

安装向导默认展示 Windows 步骤，同时提供 macOS 和 Linux 的差异说明。步骤包括：

1. 安装构建依赖
2. 构建 Native Host
3. 在 Chrome 中加载未打包扩展
4. 获取扩展 ID
5. 注册 Native Messaging Host
6. 重启 Chrome
7. 检查桥接状态
8. 允许测试站点并执行示例调用

每一步包含命令、操作位置、预期结果和常见失败原因。完成状态只保存在本机 `localStorage`，并提供清除进度按钮。

## 6. 交互原则

- 默认先显示结论和图示，细节通过展开面板逐层呈现
- 所有可点击图形同时支持键盘操作和可读标签
- 表格在窄屏切换为分组卡片，不强制缩小文字
- 流程图在窄屏可横向浏览，并提供等价的步骤列表
- 动效只表达流向、状态变化或页面切换
- 系统设置要求减少动画时，使用静态状态切换
- 不用悬停作为唯一信息入口
- 外部链接、复制操作和筛选状态提供明确反馈

## 7. 内容模型

现有 Markdown 文档继续作为事实来源和维护参考。网页使用一个结构化内容层承载：

- 页面元数据
- 导航顺序
- 架构组件
- 请求步骤
- 能力条目
- API 方法
- 错误码
- 安全风险和保护措施
- Codex 对比条目
- 安装步骤

架构图、搜索、能力矩阵、API 页面和差异页必须读取同一份结构化数据，避免名称或状态不一致。

## 8. 本机数据与隐私

网站不连接真实 Chrome 桥接器，不请求浏览器扩展权限，不读取浏览历史、Cookie、标签页或本机文件。

浏览器本地仅保存：

- 安装步骤完成情况
- 用户选择的显示偏好
- 最近阅读页面或位置

所有本机状态均可清除，不包含敏感数据。

## 9. 错误与降级

- 无搜索结果：提供中文提示和相关分类入口
- 无效路由：展示站内 404 页面和返回首页按钮
- 复制失败：选中代码并提示手动复制
- JavaScript 不可用：核心正文和静态表格仍可阅读
- 动画不可用：流程播放器退化为编号步骤列表
- 不支持 `localStorage`：安装向导仍可使用，但不保存进度
- 内容数据缺失：构建阶段失败，不在运行时静默隐藏

## 10. 技术结构

使用 Sites 提供的本地网站项目结构，保持静态内容优先和多路由页面。网站不依赖数据库、上传、认证或外部连接器。

建议组件边界：

- `SiteShell`：全站导航、搜索入口和响应式布局
- `ArchitectureMap`：组件关系、视图切换和详情面板
- `RequestStepper`：请求流程播放和示例载荷
- `CapabilityMatrix`：能力分类、状态和筛选
- `ApiExplorer`：API 索引、详情、示例和深链接
- `SecurityMap`：信任边界、风险和保护措施
- `DifferenceMatrix`：Codex 架构与能力差异
- `SetupGuide`：安装步骤、预期结果和本机进度
- `SearchDialog`：全局索引和键盘导航

组件只依赖结构化内容接口，页面负责组合，不把全部逻辑放入单个页面文件。

## 11. 验证标准

### 内容完整性

- README 的能力、安装、MCP、JavaScript 客户端、安全和许可信息全部映射到网页
- ARCHITECTURE 的组件、数据流、策略和失败边界全部映射到网页
- API 文档的每个方法和错误码均可搜索和访问
- SECURITY 的威胁、默认保护、加固项和操作建议全部映射到网页
- CODEX-DIFFERENCES 的每个架构与能力比较项均出现在差异矩阵
- 中英文术语在所有页面使用一致

### 功能验证

- 所有路由可直接访问和刷新
- 全局搜索能命中中文、API 名和错误码
- API 深链接打开正确方法
- 能力筛选和差异筛选正确
- 请求播放器前进、后退和重置正确
- 安装进度可保存和清除
- 复制按钮有成功和失败反馈

### 可访问性与响应式

- 所有交互可以键盘完成
- 焦点状态清晰可见
- 颜色不是唯一的状态表达手段
- 正文和交互控件满足可读对比度
- 桌面、平板和手机宽度下不存在关键内容溢出
- 减少动态效果设置生效

### 工程验证

- 生产构建成功
- 内部链接检查通过
- 结构化内容完整性测试通过
- 搜索索引测试通过
- 浏览器控制项目原有测试继续通过

## 12. 成功标准

一名熟悉开发但不了解本项目的读者，应能在文档站中：

1. 在五分钟内说清完整控制链路和每层职责
2. 找到任意浏览器能力对应的 API、参数和安全要求
3. 理解本项目与 Codex 的相同点、差异和不可复用边界
4. 按安装向导完成本机安装并知道每一步的预期结果
5. 在不阅读全部 Markdown 原文的情况下获得完整且不失真的技术理解
